# ReviewGate audit — 2026-09-14

## Summary

The engine's git-tree model (snapshot A at `send`, snapshot B at `turn_end`, `diff-tree A B`) is sound for what it covers, but three things let changes slip past review with no signal: **edit tools are auto-allowed without any path containment** (a `Write` to `~/.zshrc` never prompts and never appears), **`.gitignore`d paths are invisible by construction** (`git add -A`), and **the gate has no persistence** — a sidecar crash, engine respawn, or the user's own `open_project` after a session death silently drops the pending list while Claude's edits stay on disk. On the review-speed side, both clients discard the engine's `truncated` flag, have no next/prev-file navigation, no intraline diff, and no friction on "Accept all". Recommended first step: a "sensitive/outside-repo path" deny+flag in the PreToolUse hook, then gate persistence in `<gitdir>/`, then a `restart_session` command that keeps the gate.

## Root Cause

Most core-purpose gaps trace to one design assumption: **the review boundary is "the git worktree, as git sees it"** (`git add -A` through a temp index) and **the safety boundary is "tool name"** (edit tools auto-allowed, everything else `ask`). Neither boundary is path-aware, and the gate state that ties them together exists only in process memory. The UX gaps are mostly clients discarding engine information they already receive (`truncated`, `scope`, `lastError`, `blockedReason` semantics).

## Trade-offs

| Option | Pros | Cons |
|---|---|---|
| Deny out-of-repo edits in the hook (1.1) | Closes the hole with ~15 lines; no protocol change | Blocks legitimate `~/.claude/` edits Claude sometimes does; needs an `ask` variant |
| Persist gate in `<gitdir>` + `refs/reviewgate/*` (1.3) | Survives crash/respawn/reopen; makes `restart_session` trivial | Writes refs into the user's repo (visible in `git for-each-ref`); needs cleanup on `close_project` |
| Cap/heuristic on post-Bash snapshot (3.3) | Large-repo usability | Budget counting after `Bash` becomes best-effort; the turn-end collection still catches everything |
| Per-hunk accept via `git apply -R` (1.12) | Faster review of mixed hunks | Breaks the single invariant "reject = restore from A"; every hunk op re-snapshots B; M effort with subtle rename/binary cases |
| Engine-owned settings defaults/template (5.2) | One source of truth; live template re-render | Protocol bump (`ready.defaults`); both clients change at once |

## Recommended next 5 (in order)

1. **Path containment for edit tools + `changedOutside`/ignored-files signal (1.1, 1.2)** — the two ways Claude can change files with zero trace today; both are S effort in `hooks.ts`/`gate.ts`.
2. **Persist the gate in `<gitdir>/` with pinned refs, and add `restart_session` (1.3, 1.4)** — turns crash/respawn/session-death from "review silently lost" into "review resumes"; unlocks 3.1.
3. **Wire `resume` + transcript persistence (3.1)** — cheap once 2 exists; without it every restart loses Claude's memory of what was accepted/rejected.
4. **Electron IPC hardening: whitelist command types, gate `rg:e2e:readFile`, guard `setWindowOpenHandler` (2.1, 2.2)** — S effort, closes a full-engine-compromise path before the Windows rollout.
5. **Surface `truncated`, add next/prev-file + request-changes shortcuts, and put a summary sheet on Accept all (1.9, 1.10, 1.11)** — the cheapest review-speed and review-fidelity wins, all client-side, no protocol change.
